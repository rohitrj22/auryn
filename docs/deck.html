Auryn

A memory engine for AI agents, on FalkorDB.

And a crew of agents built on it, triaging GitHub issues.

The problem

An agent forgets everything when its process stops.

It also cannot see what another agent learned.

Those are two problems with one fix. Put the memory outside the agent, in a shape where things connect.

What breaks without it

What goes wrongWhat is not connected
A user explains the same thing twice this week's conversation to last week's
Two agents investigate the same bug one agent's findings to another agent's
Nobody can say why a verdict was reached a conclusion to the evidence behind it

A context window closes all three. Until it closes.

Three kinds of memory

KindHoldsWhy separate
EVENT
episodic		 Something that happened, with a time Counting events is how it found five issues sharing one bug
FACT
semantic		 Something that stays true The agent carries it every turn. It never searches for it.
PROCEDURE
procedural		 How to act, and when The rule lives in memory, not in code

Everything meets at a topic

note from agent A ──┐ │ note from agent B ──┼──▶ TOPIC "session-expiry" │ a job to be done ──┘

Two agents file under one topic, weeks apart. Their notes then find each other.

A job is filed under topics too. That arrow is what makes a handover work.

One graph per user

A leak is impossible, not forbidden.

The graph name is the user. A query names one graph. There is no syntax for reaching a second one.

Memory(tenant="alice")   →  graph "alice"
Memory(tenant="bob")     →  graph "bob"   unreachable from alice

No tenant filter anywhere. So no forgotten filter either.

Demo

Ten GitHub issues. Six agents. One memory.

What you just saw

  • Six agents in six processes. They send each other nothing.
  • One investigated the shared bug. Four avoided repeating it.
  • Two lost a race for the cause. Two read it from memory.
  • Nobody told it session expiry was the main problem. It counted.
  • The assignee started with two strings and read fifteen notes.

Bring your own agent

Auryn does not own your loop. It never calls a model.

mem = Memory(tenant=user_id)

def chat(message):
    context = mem.standing() + mem.recall(message)   # before
    reply   = your_own_llm(context, message)         # your code
    mem.remember(FACT, a_fact_from(reply), ...)      # after
    return reply

Start FalkorDB. Point Auryn at it. Two lines around what you already wrote.
